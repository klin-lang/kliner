# Stage 6 — x86-64 backend and static ELF64

Status: **done** (stage 6). The choices below are
[C14](02-core-subset.md#c14-stage-6-x86-64-backend--decided-2026-10-24),
**DECIDED (2026-10-24)**. C13 (wrapping at the type, shift counts ≥ the width
give 0 / −1, C memory layout, IR calling convention / frame slots) is
kept as decided.

```
kliner-build [-I DIR]... FILE.kl -o OUT     # load + check + lower + x86-64 + ELF64
tools/kliner-build/out/main -I rt/linux_x86_64 -I rt -I src tools/kliner-run/main.kl -o kliner-run
```

The frontend (loader, checker, lowering) is the same as `kliner-run`'s,
and its errors are printed the same way (`line:col: message`, exit 1).
Backend errors are `error: MESSAGE` (exit 1); a failing write is
`kliner-build: error: ERRNO`. Native programs use the real runtime
`rt/linux_x86_64/sys.kl`: `sys.call6` has no body and becomes the IR's
`Sys` instruction, i.e. the `syscall` instruction. Nothing else is
linked: no libc, no crt, no linker, no dynamic loader.

Code: `src/x64/enc.kl` (buffer, instruction encoder, fixups),
`src/x64/gen.kl` (IR → machine code, helpers, `_start`),
`src/x64/elf.kl` (ELF64 image), `tools/kliner-build`. No globals
(C7.3); everything hangs off `Cg`.

## Encoder

A small, table-free encoder for the subset the codegen needs: REX
(`W R X B`), one- and two-byte (`0F xx`) opcodes, ModRM with SIB for
`rsp` / `r12` bases and the shortest displacement (none / 8 / 32 bit),
`mov r, imm` (imm32 sign-extended or imm64), `rip`-relative `lea`,
`jmp` / `jcc` / `call` with rel32 fixups, rel8 / rel32 local jumps
inside helpers. Fixups: `FX_LAB` (IR label), `FX_FN` (function),
`FX_HELP` (helper), resolved when all code is out; `FX_DATA` /
`FX_BSS` (string data / globals), resolved by the ELF writer once the
data address is known. `objdump -d` decodes every emitted byte
(no `(bad)` on any Kliner tool).

## Code generation

No register allocator (the stage-6 plan "locals in stack slots"):

- **Frame.** `push rbp; mov rbp, rsp; sub rsp, N`. IR register `r` lives
  at `[rbp − 8(r+1)]`; the IR's frame slots (locals with an address,
  temporaries for aggregates) below them. `N` is a multiple of 16.
- **Values** are computed in `rax` / `rcx` and **normalized to the
  type** before the store (`movsx` / `movzx` / `movsxd` / `mov r32`), so
  every register slot always holds the value sign- or zero-extended to
  64 bits. That is C13.2: every operation wraps at its type.
- **Division.** A zero divisor jumps to trap 1. A signed divisor −1 is
  done as `neg` / 0 (no `#DE` on `MIN / −1`; wraps as C13.2). Unsigned
  is `xor edx, edx; div`.
- **Shifts.** The count is compared (unsigned) with the width of the
  type: in range → `shl` / `shr` / `sar` with `cl`; out of range → 0, or
  `sar 63` (−1 / 0) for a signed `>>`. That is C13.2 (C: undefined; the
  hardware masks the count; Klin's C did so too until K-B6 was fixed).
- **Compares** `cmp` + `setcc` + `movzx`; signed conditions only for
  signed types.
- **Memory** loads / stores at the IR type's width, C layout (C13.3).
  `Copy` of ≤ 64 bytes in ≤ 8 pieces is inline: all pieces are loaded
  into scratch registers before the first store, so overlapping copies
  are exact. Bigger copies call the `memmove` helper (`rep movsb`,
  backwards with `std` when the destination is above the source).
  `Zero` ≤ 64 bytes: inline stores; bigger: `rep stosb`.
- **Jumps.** `Jmp` to the next label is dropped; `Br` whose then-label
  follows becomes a single `jz else`.
- **Globals and string data** `lea r, [rip + rel32]` into `.data` /
  `.bss`. `FnRef` of a body-less function is 0 (calling it traps).
- **Calls** — Kliner's own convention (not SysV): the caller reserves
  `align16(8n)` bytes, stores argument `j` at `[rsp + 8j]`, `call`s,
  releases them; the callee copies `[rbp + 16 + 8i]` into its parameter
  slots. The result comes back in `rax` and is normalized by the
  caller. Aggregates go by address, results through `sret` (C13.4).
  `CallInd` checks for a null fn value (trap 3).
- **`Sys`** loads `rax, rdi, rsi, rdx, r10, r8, r9` and executes
  `syscall`.
- **Dead code.** Only functions reachable from `main` and `$init`
  (through `Call` and `FnRef`) are emitted: `hello` 53 KB → 18 KB.

### Helpers, traps, `_start`

- `_start`: keeps the initial `rsp` (argc / argv), `mmap`s a 1 GiB
  `MAP_NORESERVE` stack, makes its lowest 64 KiB the `sigaltstack` and
  the next 1 MiB a `PROT_NONE` guard, installs a `SIGSEGV` handler
  (`SA_ONSTACK | SA_SIGINFO | SA_RESTORER`), switches `rsp`, calls
  `$init` and `main` (with the `[][]u8` of argv when `main` takes it;
  `argv[0]` is the binary path, as with Klin), and passes `main`'s
  result to `exit_group`. If the `mmap` fails (e.g. `ulimit -v`), the
  program runs on the kernel's stack without the handler.
- Traps print `kliner: trap: MESSAGE` on stderr and exit 134, like
  `kliner-run`: `division by zero`, `end of a function without
  \`return\``, `call through a null fn value`, `stack overflow` (fault
  address in the guard), `invalid memory access` (any other `SIGSEGV`).

## ELF64

`ET_EXEC`, x86-64, static: ELF header + 3 program headers, then code.

| segment | address | contents |
|---|---|---|
| `PT_LOAD` R X | `0x400000` (file offset 0) | headers + `.text` |
| `PT_LOAD` R W | `0x10000000` + file offset | `.data` (strings), then `.bss` (globals, `memsz` only) |
| `PT_GNU_STACK` RW | — | non-executable stack |

Sections for tools: `.text`, `.data`, `.bss`, `.symtab` (every function
and helper as a local `FUNC`, `_start` global), `.strtab`,
`.shstrtab`; so `objdump -d`, `readelf -s` and `gdb` show names. No
`PT_INTERP`, no `PT_DYNAMIC`, no relocations. The file is written with
mode 0755.

the target of stage 7.

## Limitations

- Linux x86-64 only; no floats (none in the subset), no `cimport`.
- Code is 3–4× bigger and slower than gcc `-O0` (see above).
- Any `SIGSEGV` outside the guard is "invalid memory access" (no
  address / source position); without the `mmap`ed stack (fallback)
  a stack overflow is a plain `SIGSEGV`.
- The 1 GiB stack is reserved (`MAP_NORESERVE`), not committed; deep
  recursion is limited by it, not by a call counter (`kliner-run`
  caps at 10 000 calls).
- `argv[0]` is the binary path (as with Klin); under `kliner-run` it is
  the `.kl` path (C13.8).

## Klin bug K-B6 (fixed in e6058dc)

**Fixed in Klin main `e6058dc` (#361, D26)**, checked 2026-10-24: the
repro prints `0`, `0` with Klin too, and `tests/ir/c13` (formerly
`tests/x64/c13`) gives the same output with Klin, `kliner-run` and the
native binary. Before the fix: Klin's C output shifted `i32` / `u32` / `i64` / `u64` with C's `<<` /
`>>`; for a count ≥ the width C is undefined and x86 masks the count,
so `1i32 << 32` is 1 and `u64 max >> 64` is `max`. Kliner (C13.2,
DECIDED): 0 and 0 (−1 for a negative signed `>>`). `u8` / `i8` / `u16`
/ `i16` are fine (promoted to `int`). Repro (`klin main.kl` prints
`1`, `-1`; `kliner-run` and native print `0`, `0`):

```klin
module main
import os
import out
fn shl(a: i32, n: i32): i32 {
    return a << n
}
fn shr(a: u64, n: u64): u64 {
    return a >> n
}
fn main() {
    let mut o = out.Out.stdout()
    o.dec(cast(i64, shl(1, 32)))
    o.nl()
    o.dec(cast(i64, shr(18446744073709551615, 64)))
    o.nl()
    o.flush_quiet()
    os.exit(0)
}
```

`c13` lived in `tests/x64` until the fix (the `tests/ir` goldens must
equal the Klin builds). K-B5 (no wrapping of `u8 + u8` etc.) and K-B4
(zero `str` was NULL) are fixed in `e6058dc` too (D26, D27).
