# Stage 7 — RV64 backend (Linux RISC-V 64)

Status: done on `qemu-riscv64` (user mode); not yet run on a real board.
Decisions: [C15](02-core-subset.md#c15-stage-7-rv64-backend--partly-decided-2026-10-24)
(C15.1 DECIDED 2026-10-24, the rest PROPOSED).

```
kliner-build --target rv64 -I rt/linux_riscv64 -I rt -I src FILE.kl -o OUT
kliner-build --target x64  -I rt/linux_x86_64  -I rt -I src FILE.kl -o OUT
```

`--target` accepts `x64` / `x86_64` / `rv64` / `riscv64`; the default
is the host the compiler itself was built for (`sys.ARCH` of its
runtime). Every `kliner-build` is a cross compiler: the x86-64 one
makes RV64 binaries and the other way round, byte for byte the same.
The runtime directory still has to match the target (`-I
rt/linux_riscv64`), see [limitations](#limitations).

## Layout

| Path | What |
|---|---|
| `src/back/back.kl` | shared by both backends: helper / trap ids, trap texts, reachable functions (C14.4), constant normalization, fall-through test, stack constants (C14.2) |
| `src/back/elf.kl` | the static ELF64 writer (C14.5) for any machine: 3 `PT_LOAD`, `.text` / `.rodata` / `.bss`, `.symtab`; `x64/elf.kl` and `rv64/gen.kl` only patch their own address fixups |
| `src/rv64/enc.kl` | code buffer, fixups, RV64IM encoder (`li` of any 64-bit value, far loads / stores, `auipc` pairs) |
| `src/rv64/gen.kl` | IR → machine code, helpers (memmove, traps, SIGSEGV handler, `_start`) |
| `rt/linux_riscv64/sys.kl` | syscall numbers of the generic table (`asm-generic/unistd.h`), `ARCH`, `struct stat` layout |

The x86-64 output did not change (byte for byte the same `hello`,
`alloc`, `args`, `cat`, backend goldens) after moving the shared part
to `src/back`.

## Code

The same scheme as x86-64 (C13.4, C14.7): no register allocator, every
IR register is an 8-byte slot at `fp − 8(r+1)`, the IR's frame slots
below. Each instruction loads its operands into `a0` / `a1`, computes,
normalizes to the IR type (sign / zero extension, C13.2) and stores the
result back.

- Instructions: RV64I + M only (`mul`, `div[u]`, `rem[u]`, 64-bit
  forms; narrower types are normalized after). No C (compressed), no F
  / D, no A. `e_flags` = 0 (soft-float ABI, no RVC), so the binaries
  run on any RV64IM core, the Orange Pi RV2's included.
- Calling convention (Kliner's own, as C14.1): arguments at `sp + 8j`
  at the call (area rounded to 16), `jalr ra`, result in `a0`. Prologue
  `addi sp,-16; sd ra,8(sp); sd fp,0(sp); mv fp,sp; sp −= frame`. Only
  `fp` / `ra` are saved. `s1` (the program stack's base, for the
  SIGSEGV handler) and `s2` (the kernel's initial `sp`) are never
  touched by generated code.
- Temporaries: `a0..a7` (values, syscalls, inline copies), `t0`
  (addresses, big immediates and offsets), `t1` / `t2` (copy pointers).
- Jumps: labels `jal` (±1 MiB, so a function may not be bigger than
  1 MiB — an error, not wrong code); calls, helper jumps and addresses
  of data / globals `auipc` + `jalr` / `addi` (±2 GiB). Conditional
  jumps to a helper (traps) are an inverted branch over an `auipc`
  pair.
- C13.2 on RV64 needs no special cases where x86 needs them: `div` /
  `rem` do not fault (`MIN / −1 = MIN`, `MIN % −1 = 0`), only a zero
  divisor traps; shifts ≥ the width are tested explicitly (0, or −1
  for `shr` of a negative signed value), because RISC-V masks the
  count like x86.
- Small copies / zeroing inline (`ld` / `sd` 8 bytes, then 4 / 2 / 1;
  a copy does all loads before the first store, so overlap is safe).
  Bigger copies go through the `memmove` helper (8 bytes at a time when
  both pointers are 8-aligned, else bytes), bigger zeroing is an inline
  8-byte loop with a byte tail.

## `_start`, syscalls, signals

`_start` does what the x86-64 one does (C14.2): `mmap` a 1 GiB
`MAP_NORESERVE` stack (64 KiB alternate signal stack, 1 MiB
`PROT_NONE` guard), `sigaltstack`, `rt_sigaction(SIGSEGV)` with
`SA_SIGINFO | SA_ONSTACK` (RISC-V has no `SA_RESTORER`: the handler
never returns), `$init`, `main(args)` with `args` built from argc /
argv as a `[]str`, `exit_group(main's i32)`. If the `mmap` fails it
runs on the kernel's stack. A fault in the guard is `kliner: trap:
stack overflow`, any other `kliner: trap: invalid memory access`, both
exit 134 (C14.3).

Syscalls: `ecall` with the number in `a7`, arguments in `a0..a5`,
result in `a0` — the same `sys.syscallN` intrinsics as on x86-64, with
the numbers of the generic table (`openat` 56 instead of `open`,
`newfstatat` 79, `getdents64` 61, `mmap` 222, `exit_group` 94, …).
`rt/os.kl` uses `openat(AT_FDCWD, …)` everywhere already, so only the
numbers and the `st_mode` offset (16 instead of 24) are per target.

## Tests (`scripts/test.sh`, stage 7 section)

Run when `qemu-riscv64` is on `PATH` (Debian / Ubuntu: `apt install
qemu-user`; `QEMU_RISCV64=…` overrides), skipped otherwise:

- `hello` is a static ELF64 RISC-V; `hello` / `alloc` / `args` / `cat`
  give the same stdout, stderr and exit code as on x86-64;
- the `tests/ir` goldens; traps (division by zero, stack overflow:
  exit 134);
- Kliner's `kliner-lex` (82 files), `kliner-parse` (94), `kliner-check`
  (goldens + programs), `kliner-ir` built for rv64 = the Klin-built
  tools; `kliner-run` for rv64 passes the `tests/ir` goldens;
- **cross fixpoint**: `kliner-build` for rv64 rebuilds itself under qemu
  byte for byte, the x86-64 `kliner-build --target rv64` makes the same
  file, and the rv64 one with `--target x64` makes the same x86-64
  `kliner-build` as the native one.

Sizes (bytes, static, with `.symtab`):

```sh

         trap:tests/ir/only/trap deep:tests/ir/only/deep \

tar czf /tmp/rv2-src.tgz src rt tools/kliner-build
scp /tmp/rv2/* /tmp/rv2-src.tgz orangepi@BOARD:kliner-rv/
```

On the board (`ssh orangepi@BOARD`):

```sh
cd ~/kliner-rv && chmod +x hello args cat trap deep kliner-lex kliner-build
uname -m                          # riscv64
./hello; echo "exit $?"           # "hello, kliner" ... "to stderr ENOENT errno 999", exit 3
```

## Limitations

- RV64IM only: no compressed instructions (RVC usually saves
  25–30 % of code size), no floats (none in the subset).
- Slots further than ±2 KiB from `fp` cost `li` + `add` + `ld` (up to 4
  instructions instead of 1); big functions (the checker, the IR
  lowering) have many of them. A register allocator (stage 8) removes
  most slot traffic.
- A function must fit in ±1 MiB of `jal` (a clear error otherwise;
  the biggest Kliner function is far below).
- Not tested on hardware yet; qemu user mode accepts misaligned loads
  / stores silently.

## Weak points: where the backend was too tied to x86-64

Found while porting; the first four are fixed in this stage:

1. **The ELF writer** lived in `src/x64/elf.kl` with `EM_X86_64`, rel32
   fixups and the x86 helper names inside → `src/back/elf.kl` takes the
   machine, the code, the data and the symbols; each backend patches
   its own fixups.
2. **Reachability, traps, constants** (`reach`, trap messages, `cnorm`,
   stack sizes) were copies inside `x64/gen.kl` → `src/back/back.kl`.
3. **`struct stat` layout**: `rt/os.kl` read `st_mode` at offset 24
   (x86-64) → `sys.STAT_MODE` per target (RV64 / ARM64: 16).
4. **`memfd_create` 319** was a literal in `src/vm/vm.kl` →
   `sys.NR_MEMFD_CREATE`.
5. **`kliner-run` passes syscalls through by number** (C13.6), using
   the numbers of the *program's* `sys` module. On an RV64 host it must
   be given `-I rt/linux_riscv64` (with the x86-64 runtime it would make
   x86-64 syscalls on RISC-V). Proposed: the driver picks
   `rt/linux_<target>` itself (C15.5).
6. **`rt/bootstrap`** (Klin + a C shim) has x86-64 numbers and layouts;
   building Kliner with Klin *on* an RV64 host needs its own bootstrap
   `sys` (not needed: cross-build on x86-64 and copy).
7. **No alignment in the IR**: `Copy` / `Zero` carry a size but no
   alignment, so inline copies use `ld` / `sd` on possibly misaligned
   addresses. That is legal on Linux RISC-V, but on hardware without
   fast misaligned access the kernel / firmware emulates it (slow).
   x86-64 does not care. Proposed: the IR records the alignment (C15.8).
8. **Compare + branch**: the IR has `cmp` into a register then
   `jz/jnz`; RISC-V has fused `beq/blt/…`. Same fix as on x86-64
   (fused compare + branch, stage 8).
