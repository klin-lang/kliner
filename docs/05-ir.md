# Stage 5 — IR and IR interpreter

Status: **done** (stage 5). Decisions here follow
[C13](02-core-subset.md#c13-stage-5-ir--partly-decided-2026-10-24): labels as block boundaries, wrapping at
the type, C layout and the calling convention / frame slots are
**DECIDED (2026-10-24)**; the rest is **PROPOSED**, unless it restates
K9 (linear three-address code, virtual registers, explicit widths, no
SSA — DECIDED).

```
kliner-ir  [-I DIR]... FILE          # dump the IR of a program (stdout)
kliner-run [-I DIR]... FILE.kl [ARG]...
                                     # load + check + lower + interpret
```

Both run the stage-4 frontend (loader, checker) first; a checker error
is printed as by `kliner-check` (`line:col: message`, exit 1), a
lowering error the same way (`… is not supported yet`, exit 1).
`kliner-run` writes its own errors to stderr, so stdout is the
program's. Interpreted programs use the real runtime:
`-I rt/linux_x86_64 -I rt` (`sys.call6` without a body becomes the
`Sys` instruction).

Code: `src/ir/ir.kl` (tables, builder, layout, dump), `src/ir/lower.kl`
(statements, functions, globals), `src/ir/lexpr.kl` (expressions,
calls, `!T`), `src/vm/vm.kl` (interpreter), `tools/kliner-ir`,
`tools/kliner-run`. State through `*mut` only, no globals (C7.3).

## Program

A `Prog` holds one instruction table for all functions, an argument
pool (call arguments are register numbers in `args`), a label table,
the function table, the string data and the size of the globals.

- **Functions** keep the checker's function index (`fns[i]` is checker
  function `i`), so calls need no name lookup; `fns[nfn]` is `$init`,
  which stores the initializers of the globals in declaration order
  and runs before `main`. Kinds: 0 a body, 1 `sys.call6` (calls become
  `Sys`), 2 no body (`cimport` / other body-less functions: a call is
  "not supported yet").
- **Names** in the dump: `module.name`, methods and associated
  functions `module.Type.name`.
- **Labels** are numbered per function; `labs[f.lab + id]` is the
  instruction index. Basic blocks are implicit: a block starts at a
  label and ends with `jmp`, `br`, `ret` or `trap` (K9's blocks without
  a block table; the backend can split on labels).
- **Data**: string literals, each followed by a NUL and aligned to 8;
  `data K` is the address of byte K.

## Registers and types

Registers `r0 …` are per function, 64 bits, **not SSA** (`r25 = mov`
can be written on two paths of an `or`). Parameters are `r0 … r(np-1)`;
a function returning an aggregate gets the result address in `r0`
(`sret`). Every instruction that produces a value has a type, and the
value is kept **normalized** to it: sign-extended for `i8 … i64`,
zero-extended for `u8 … u64`, `ptr` is 64 bits. So widening a value is
free and only narrowing (`conv`) or arithmetic needs work.

| IR type | Klin |
|---|---|
| `i8 i16 i32 i64 u8 u16 u32 u64` | the same; `bool` is `u8`, `usize` `u64`, `isize` `i64`, enums their base type |
| `ptr` | pointers, `fn` values, addresses of aggregates |

Floats are rejected by the checker already (C3); the lowering repeats
the check for its own entry points.

## Memory layout

C's natural layout, the same as Klin's C output, so a program sees the
same `sizeof`-like values (`&a[1] - &a[0]`) under both:

- struct: fields in order, each aligned to itself, size rounded up to
  the largest alignment; array `[N]T`: N × size(T);
- slice `[]T` / `str` slice: `{ptr @0, len i32 @8}`, size 16; `str`
  itself is a `ptr` (C string, `s.len` = strlen);
- `!T`: `{is_err u8 @0, err i32 @4, value @8}`, size
  roundup(8 + size(T), max(4, align(T))); `!void` is 8 bytes;
- every local lives in a frame slot (`slot K` = frame + K); registers
  are temporaries. Aggregate parameters and receivers, and `mut`
  receivers, are passed by address: the slot holds the pointer.
  Aggregate arguments are always copied into a fresh temporary first,
  so a callee never sees the caller's object (value semantics).

## Instructions

| dump | meaning |
|---|---|
| `rD = const.T K` | constant |
| `rD = slot K` / `glob K` / `data K` | address of a frame slot / global / string data |
| `rD = fnref NAME` | a function as a value |
| `rD = mov.T rA` | copy a register |
| `rD = load.T [rA+K]` / `store.T [rA+K], rB` | memory, width T |
| `rD = add.T rA, rB` | `add sub mul div rem and or xor shl shr`: wrap at T; `div`/`rem` signed or unsigned by T, trap on 0, `MIN / -1` wraps |
| `rD = eq.T rA, rB` | `eq ne lt le gt ge`: 1 / 0; signedness from T |
| `rD = neg.T rA` / `not.T rA` | |
| `rD = conv.T.S rA` | S → T (truncate / extend) |
| `copy rA, rB, K` / `zero rA, K` | K bytes from rB to rA (memmove) / zero K bytes |
| `L5:` / `jmp L5` / `br rA, L1, L2` | labels, jumps |
| `rD = call NAME(rA, …)` / `rD = callind rF(…)` | calls (no `rD =` when unused) |
| `ret rA` / `ret` | return |
| `rD = sys(rN, rA, …)` | syscall: number + 6 arguments |
| `trap K` | 1 division by zero, 2 end of a function without `return`, 3 null `fn` value |

Shift counts are unsigned; a count ≥ the width gives 0 (or −1 for `shr`
of a negative signed value). In C (Klin) this is undefined behaviour,
so programs that rely on it differ — none of the tests does.

## Lowering

From the checked AST, using what the checker recorded: the resolved
type of every expression (`rt`) and, new in stage 5, what each name
refers to (`File.rf`: global, constant or function + index, set by the
checker where it resolves the name). Nothing is resolved twice.

- Expression types: `rt` may be the context type (an untyped constant
  materialized to `i64`); loads use the declared type of the local,
  field, element or pointee, and the normalized register makes the
  implicit widening free.
- `&&` / `||` short-circuit through a shared result register.
- `match` (statement and expression): a chain of compares; `else` last.
- `defer`: emitted in reverse at the end of the scope, at `break` /
  `continue` (the defers inside the loop) and at `return` (all).
  While a deferred statement is emitted, the locals declared after it
  are hidden, so it sees the names it saw where it was written.
- `for i in a..<b`: C's `for` — the end is evaluated each iteration,
  `continue` jumps to `i += 1`.
- `!T`: `error(E)` writes `{1, E}`; `x!` returns the error from the
  current function (running its defers); `x or { … }` binds `err`.
  `main` returns `i32` (its `return` value; 0 at the end).
- `let x = y` evaluates `y` before `x` exists (`let x = x + 1`).

Not supported yet (the checker accepts them, the lowering does not):
calls of body-less functions other than `sys.call6` (`cimport`),
pointer arithmetic, more than 60 call arguments, more than 64 targets
of a multi-assignment. Each gives `line:col: … is not supported yet`.

## Interpreter

`src/vm/vm.kl`. Memory is the host's: the program mmaps its own arenas
through syscalls, frames come from one 256 MiB mmap'd stack, the
registers from a 128 MiB register stack, globals from the interpreter's
arena; loads and stores use the addresses directly. A call is a host
call (recursion in `exec`), so the call depth is capped at 10 000
(`MAXDEPTH`, the 8 MiB host stack holds about 20 000); deeper recursion
traps with `stack overflow` like a full frame or register stack.
Registers are written normalized to the
type of the instruction, as in the IR definition.

Syscalls pass through to the kernel, with one emulation:
`openat("/proc/self/cmdline")` returns a memfd holding the program's
own argv (the `.kl` path, then the arguments after it), so `os.args`
works. `main(args: []str)` gets the same argv as C strings.
`exit_group` from the program ends the interpreter with that code.

Traps print `kliner-run: trap: …` to stderr and exit 134 (Klin's C
would raise SIGFPE for division by zero; that is the one
interpreter-only golden).

## Tests (`scripts/test.sh`, stage 5)

- `tests/rt/*` (hello, alloc, args, cat) under `kliner-run`, same
  expectations as their Klin-built binaries.
- `tests/ir/NAME/main.kl` with `main.out` (stdout + `exit N`, run with
  arguments `x y`): arith (all widths, wrapping, division, shifts,
  conversions), control (loops, match, defer order, recursion, `fn`
  values, short-circuit), data (structs by value, arrays, slices,
  methods, globals, constants, strings, destructuring), errors (`!T`,
  `!`, `or`, defers on the error path), exit (`main(args): i32`). Each
  is checked twice: `kliner-run` = golden and Klin-built binary =
  golden.
- `tests/ir/only/`: `dump` (the `kliner-ir` format, `out.ir`), `trap`,
  `deep` (unbounded recursion), `unsup` (interpreter-only).
- Self: `kliner-lex` and `kliner-parse` **interpreted** on every `.kl`
  file of Kliner plus the lexer / parser goldens give byte-identical
  output and exit codes to the Klin-built tools; `kliner-check`
  interpreted checks `tools/kliner-run` and a failing golden the same
  way; `kliner-ir` interpreted dumps the IR of `kliner-run` (≈122k
  lines) identically. `kliner-run` also runs itself (`kliner-run
  kliner-run hello`).

Speed: about 75× slower than the Klin-built tool (kliner-check on
itself: 2.2 s vs 0.03 s). Enough for tests; the backend is stage 6.

## Differences from Klin (Klin → C → gcc)

- **K-B5 (Klin bug, fixed in main `e6058dc`, #361, D26; checked
  2026-10-24: Klin now prints 2, 15 and no "u8 sum" line, as Kliner)**:
  arithmetic on `u8` / `i8` / `u16` / `i16` was not wrapped to the
  type — C's integer promotion leaked into values of the narrow type
  (Klin main `a66ffbd` and `f9f5471`, `klin main.kl` with
  `-I rt/bootstrap -I rt`):
  ```kl
  module main
  import os
  import out

  fn main() {
      let mut o = out.Out.stdout()
      let k: u8 = 129
      o.dec(cast(i64, k << 1))   // Klin: 258, Kliner: 2
      o.nl()
      let a: u8 = 0xf0
      o.dec(cast(i64, ~a))       // Klin: -241, Kliner: 15
      o.nl()
      let x: u8 = 200
      let y: u8 = 100
      if x + y > 255 {           // Klin: true, Kliner: false (44)
          o.lit(b"u8 sum > 255")
          o.nl()
      }
      o.flush_quiet()
      os.exit(0)
  }
  ```
  Storing the result into a `u8` variable truncates in both, so the
  older goldens do that (tests/ir/arith); `tests/ir/c13` and
  `tests/ir/wrap_assign` test the unwrapped cases directly (need
  `e6058dc`). The IR wraps every operation at its
  type ([C13.2](02-core-subset.md#c13-stage-5-ir--partly-decided-2026-10-24)).
- Shift counts ≥ the width: 0 / −1 in the IR; in Klin's C undefined
  until `e6058dc` (K-B6, D26), now the same — `tests/ir/c13`.
- Division by zero: SIGFPE in C, `trap` (exit 134) in the interpreter.
